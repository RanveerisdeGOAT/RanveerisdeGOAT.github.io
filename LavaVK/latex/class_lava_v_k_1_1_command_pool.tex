\doxysubsection{Detailed Description}
Opaque container managing GPU memory pools for command buffer allocation. 

A \doxylink{class_lava_v_k_1_1_command_pool}{Command\+Pool} encapsulates a Vk\+Command\+Pool bound to a specific Queue\+Type. It maintains ownership of all Command\+Buffers allocated from it; individual {\ttfamily \doxylink{class_lava_v_k_1_1_command_buffer}{Command\+Buffer}} handles are non-\/owning views into storage kept alive by their {\ttfamily \doxylink{class_lava_v_k_1_1_command_pool}{Command\+Pool}}, and are invalidated when the pool is destroyed or moved-\/from. {\ttfamily \doxylink{class_lava_v_k_1_1_device}{Device}} normally owns one {\ttfamily \doxylink{class_lava_v_k_1_1_command_pool}{Command\+Pool}} per requested {\ttfamily Queue\+Type}, created lazily via {\ttfamily \doxylink{class_lava_v_k_1_1_device_a22b0ab567bd146918dd2bdfe88fc93ab}{Device::\+get\+Command\+Pool()}}, so applications typically do not construct a {\ttfamily \doxylink{class_lava_v_k_1_1_command_pool}{Command\+Pool}} directly.

Example, allocating one command buffer per frame in flight:\+
