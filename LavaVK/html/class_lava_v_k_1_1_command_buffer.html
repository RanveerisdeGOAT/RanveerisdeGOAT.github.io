Detailed Description

Wrapper around VkCommandBuffer for recording GPU rendering and compute instructions.

Command buffers are allocated from a CommandPool and submitted to a GPU queue for execution. Members are marked const as recording commands modifies the GPU recording state pointed to by the handle, rather than the C++ handle itself. CommandBuffer is a non-owning handle: it is allocated and freed by its owning CommandPool, so it has no destructor of its own to manage and is freely copyable. Typical usage either records commands manually with begin()/beginRenderPass()/.../end(), or uses the higher-level record() helper that manages that whole lifecycle in one call.

Example (manual recording):

cmd.begin();
cmd.beginRenderPass(renderPass, framebuffer, extent);
cmd.bindPipeline(pipeline);
cmd.setViewportAndScissor(extent);
cmd.bindVertexBuffer(vertexBuffer);
cmd.bindIndexBuffer(indexBuffer);
cmd.drawIndexed(indexCount);
cmd.endRenderPass();
cmd.end();

Example (using record()):

cmd.record(renderPass, framebuffer, extent, [&](LavaVK::CommandBuffer &cmd) {
cmd.bindPipeline(pipeline);
cmd.setViewportAndScissor(extent);
cmd.bindVertexBuffer(vertexBuffer);
cmd.bindIndexBuffer(indexBuffer);
cmd.drawIndexed(indexCount);
});

Records an image layout transition and memory barrier using LavaVK enums.

Wraps vkCmdPipelineBarrier for the common case of a single image memory barrier, transitioning image from oldLayout to newLayout between the given pipeline stages/access masks. Queue family ownership is left unchanged (VK_QUEUE_FAMILY_IGNORED), and the barrier covers mip level 0 and array layer 0 only.

Parameters

srcAccessAccess types performed by srcStage that must be made visible.
dstAccessAccess types performed by dstStage that must wait for those writes.
aspectMaskAspect(s) of the image affected by the transition (default: color).

Pushes constants to a pipeline layout.

Wraps vkCmdPushConstants, uploading data as a fast, small block of shader-visible memory (typically used for per-draw values like a model-view-projection matrix). The push constant range covering [offset, offset + sizeof(T)) and stageFlags must match a range declared on layout.

Template Parameters
TTrivially-copyable type of the data being pushed; its size (via sizeof(T)) determines how many bytes are uploaded.
Parameters
layoutThe pipeline layout declaring the push constant range being written to.
stageFlagsShader stages that will be able to access the pushed data.
dataThe value to upload as push constant data.
offsetByte offset into the push constant range to start writing at.
